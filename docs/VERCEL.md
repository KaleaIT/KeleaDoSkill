# KaleaDoSkill: перенос на Vercel

Подготовлено 9 октября 2026 года. Код рассчитан на Node.js 24 и Next.js 16.

## Что подготовлено

- Последний визуал из Sites: рубиновый логотип, выровненные курсы, горизонтальные заголовки оплаты, прокрутка в цветах сайта.
- PostgreSQL вместо Cloudflare D1 на Vercel. Настройки редактора и лимиты сохраняются между запусками серверных функций.
- Локальная SQLite поддерживается только вне Vercel, для разработки и VPS.
- Без базы или настроек доставки сайт открывается, форма остаётся отключённой.
- Форма отправляет заявку в выбранный Telegram-чат. Успех возвращается только после подтверждения Telegram; при ошибке пользователь получает сообщение об ошибке.
- Данные заявок в базу этой версии не сохраняются. PostgreSQL хранит настройки сайта и счётчики ограничения запросов. Email-доставка не подключена.

## Важные условия

Адрес *.vercel.app не требует покупки отдельного домена. Это не означает бесплатный коммерческий хостинг: Vercel Hobby разрешён для личных некоммерческих проектов; школе нужен подходящий коммерческий тариф, обычно Pro. Тариф и оплату выбирает владелец.

Vercel и выбранная зарубежная база не подтверждают локализацию персональных данных в РФ. Перенос не устраняет вопросы из аудита РКН. Перед реальным сбором данных необходимо определить законную схему обработки. Этот документ описывает техническое подключение, не подтверждение правового соответствия.

## 1. Загрузить подготовленную версию

Рабочая ветка: `vercel-migration` в репозитории `KaleaIT/KeleaDoSkill`.

Для импорта из основной ветки сначала объедините подготовленный pull request в `main` через GitHub. Старый опубликованный сайт Sites от этого не меняется.

Альтернативный вариант без объединения: в терминале GitHub Codespaces или на своём компьютере:

```sh
git clone --branch vercel-migration --single-branch https://github.com/KaleaIT/KeleaDoSkill.git
cd KeleaDoSkill
npm ci
npx vercel login
npx vercel --prod
```

CLI предложит выбрать существующий аккаунт/команду и создать проект. Название проекта — `kaleadoskill`, если доступно. Framework — Next.js, Root Directory — корень проекта, Build Command — `npm run build`, Output Directory — автоматически.

## 2. Импортировать в Vercel

1. Откройте https://vercel.com/new и войдите в свой аккаунт.
2. Выберите Import Git Repository → `KaleaIT/KeleaDoSkill`.
3. Если репозиторий не виден, разрешите приложению Vercel доступ только к этому репозиторию.
4. Проверьте Framework Preset: Next.js, Root Directory: `./`, Node.js: `24.x`.
5. Нажмите Deploy. Первая публикация работает без формы, пока не подключены база и бот.
6. Скопируйте фактический Production URL. Его выдаёт Vercel: имя может отличаться от `kaleadoskill.vercel.app`.

## 3. Подключить постоянную базу

В проекте Vercel откройте Storage / Marketplace и подключите Neon Postgres. Проверьте тариф перед подтверждением создания. Подключите базу к Production; Preview при необходимости использует отдельную тестовую базу.

Нужна серверная переменная `DATABASE_URL` с pooled PostgreSQL connection string, выданной провайдером. Если интеграция добавляет другое имя, создайте `DATABASE_URL` с соответствующим значением. Не присылайте строку подключения в чат, не добавляйте её в GitHub.

Таблицы `settings` и `rate_limits` создаются автоматически при первом обращении. Роль приложения должна иметь право создавать эти таблицы. Если оно запрещено, администратор базы заранее создаёт:

```sql
CREATE TABLE IF NOT EXISTS settings (
  id INTEGER PRIMARY KEY CHECK(id=1),
  content TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE IF NOT EXISTS rate_limits (
  key TEXT PRIMARY KEY,
  count INTEGER NOT NULL,
  expires BIGINT NOT NULL
);
```

## 4. Настроить Telegram

1. Создайте своего бота через официальный @BotFather → `/newbot`. Сохраните токен приватно.
2. Создайте закрытую группу для владельца и коллеги; добавьте бота. Либо используйте личный чат, предварительно отправив боту `/start`.
3. В группе отправьте `/start@имя_бота`.
4. Узнайте chat_id без сторонних ботов: локально создайте `.env.local` с `TELEGRAM_BOT_TOKEN`, затем выполните `npm run telegram:chat`. Команда только читает последние обновления, не отправляет сообщения и не печатает токен. При включённом webhook getUpdates не работает; используйте отдельного бота для этой формы.
5. Выберите нужный chat_id из результата. Для группы он обычно отрицательный.

## 5. Добавить переменные Vercel

Project → Settings → Environment Variables. Настройте Production, затем выполните Redeploy.

| Имя | Значение |
| --- | --- |
| `DATABASE_URL` | Pooled connection string вашей PostgreSQL-базы |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TELEGRAM_CHAT_ID` | ID выбранного закрытого чата/группы |
| `RATE_LIMIT_SECRET` | Случайный секрет длиной минимум 32 символа |
| `SITE_URL` | Фактический Production URL, например `https://имя-проекта.vercel.app` |
| `TRUST_PROXY` | `true` при прямом размещении на Vercel без дополнительного внешнего прокси |
| `LEADS_ENABLED` | `true` для технического включения формы после настройки и решения владельца о сборе данных |

Случайный секрет можно сгенерировать на своём компьютере/в Codespaces:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Все перечисленные секреты серверные. Не добавляйте префикс `NEXT_PUBLIC_` к токену, строке базы или секрету.

Для `/admin` дополнительно нужны `ADMIN_PASSWORD` минимум 16 символов и отдельный `ADMIN_SESSION_SECRET` минимум 32 символа. Без них административный вход отключён.

## 6. Проверить публикацию

- Главная страница, логотип, курсы, раскрытие оплаты и юридические ссылки открываются.
- Production не закрыт авторизацией Vercel для обычного посетителя, если сайт должен быть публичным.
- В форме поля активны только после всех настроек.
- Отправьте одну синтетическую заявку со своими тестовыми контактами; подтвердите её получение в выбранной группе.
- При отсутствии галочки согласия отправка не проходит.
- При неправильном токене форма сообщает об ошибке, не показывает ложный успех.
- В журналах и браузерном коде нет токена и строки подключения.
- После каждого изменения переменных сделан Redeploy: сохранение переменной не меняет уже опубликованную версию.

Если формы нет: проверьте `DATABASE_URL`, `RATE_LIMIT_SECRET`, `LEADS_ENABLED`, токен и chat_id. Если ошибка 502: проверьте доступ бота к чату и его токен. Если 403: проверьте точное значение `SITE_URL`.

## Дополнительный домен позже

Settings → Domains → Add Domain. После покупки домена внесите ровно те DNS-записи, которые покажет Vercel; значения зависят от проекта. После подтверждения домена обновите `SITE_URL` и сделайте Redeploy. Для *.vercel.app этот шаг не нужен.
