# KaleaDoSkill

Адаптивный лендинг школы IT-профессий. Next.js App Router, TypeScript, Tailwind CSS 4, локальные шрифты Manrope, SQLite (встроенный `node:sqlite`, Node 24). Предоставленный оригинал логотипа сохранён, WebP и иконки получены масштабированием без изменения знака.

## Бесплатный просмотр через GitHub Codespaces

Откройте репозиторий в GitHub, нажмите **Code → Codespaces → Create codespace on main**. После подготовки среды выполните в терминале `npm run dev`. Во вкладке **Ports / Порты** откройте порт **3000** кнопкой с глобусом. По умолчанию ссылка доступна владельцу Codespace; для демонстрации другим людям можно выбрать **Port Visibility → Public**, если это разрешено настройками организации. Админка и отправка заявок без секретов отключены. Остановите или удалите Codespace после просмотра, чтобы не расходовать бесплатную квоту. Доступность бесплатных часов зависит от тарифа владельца и настроек организации KaleaIT.

Если ранее созданная среда открылась в recovery mode из-за образа `1-24-bookworm`, сначала выполните `git pull --ff-only origin main`, затем через **Ctrl+Shift+P → Codespaces: Rebuild Container** пересоздайте контейнер. Конфигурация использует официальный образ `node:24-bookworm`.

## Запуск

```sh
cd /workspace/KeleaDoSkill
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
cp .env.example .env.local
npm run dev
```

Локальные проверки выполняются на порту 3000. Для production: `npm run build`, затем `npm start`. Разработка, тесты и сборка требуют Node 24. В каждом облачном задании уже есть изолированная среда: используйте существующий checkout, не создавайте worktree без запроса пользователя.

Сайт работает без секретов, но приём заявок и админка по умолчанию отключены. Ссылка на Telegram всегда доступна. Форма не имитирует отправку, а платёжные карточки не имитируют оплату. Проверенные текстовые версии юридических документов встроены в `src/content/legal` и отображаются как доступные HTML-страницы; выводы и оставшиеся вопросы перечислены в `docs/LEGAL_REVIEW.md`.

## Структура

- `src/app/page.tsx`: серверный лендинг, секции и SEO.
- `src/components`: меню, форма, выбор курса, вход и редактор админки.
- `src/lib/content.ts`: схема данных и исходный контент; количество курсов не зашито в компоненты.
- `src/lib/db.ts`: настройки, версии редактирования и лимиты запросов в SQLite.
- `src/lib/security.ts`: подписанные сессии, CSRF по Origin, лимиты и пароль.
- `src/app/api/leads`: валидация, антиспам, отправка заявки сервером в Telegram.
- `src/app/api/admin`: защищённое редактирование, вход и выход.
- `src/lib/payments.ts`: контракт будущего официального платёжного адаптера, без активной интеграции.
- `public/brand`: оригинал и оптимизированный логотип; `public/documents`: место для утверждённых PDF.
- `tests`, `e2e`: серверные и браузерные сценарии.

## Админка

В защищённом окружении сервера задайте `ADMIN_PASSWORD` (не менее 16 символов, уникальный случайный пароль) и `ADMIN_SESSION_SECRET` (не менее 32 случайных символов). Не передавайте значения через чат и не сохраняйте в Git. Откройте `/admin` после перезапуска сервера. Пароль сравнивается через scrypt и constant-time comparison, сессии HMAC, срок 8 часов. Cookie HttpOnly, SameSite=Strict и Secure в production. Пять попыток входа за 15 минут; рекомендуется ограничить админку дополнительно на ingress/VPN и добавить MFA при росте проекта.

Редактируются первый экран, акция, курсы, цены, сроки, навыки, преимущества, что входит, FAQ, телефон, Telegram, состояния и ссылки платежей и пути документов. Правки проходят серверную схему. Защита версии предотвращает перезапись изменений другой вкладки. React экранирует контент, редактор не принимает HTML.

Контент хранится в `data/kaleadoskill.sqlite` (или `DATABASE_PATH`), не в исходных файлах. Он сохраняется после рестарта только на постоянном диске. Seed применяется один раз и не перезаписывает изменения. Смена `ADMIN_SESSION_SECRET` отзывает все сессии.

## Telegram и заявки

1. Владелец создаёт бота через BotFather и задаёт `TELEGRAM_BOT_TOKEN` на сервере.
2. Добавляет бота в нужный закрытый чат, проверяет разрешения, задаёт `TELEGRAM_CHAT_ID`. Это отдельная интеграция; ссылки на аккаунты школы не являются chat ID бота.
3. Проверяет встроенные политику, согласие и оферту со специалистом. При необходимости заменяет страницу утверждённым PDF из `public/documents`, указав путь в админке.
4. Проверяет со специалистом допустимость обработки и передачи заявок в Telegram; затем устанавливает `LEADS_ENABLED=true` и перезапускает сервер.
5. Проверяет одну согласованную тестовую заявку: реальное сообщение в нужном чате, обработку ошибки и отсутствие утечки данных.

Успех возвращается только после `ok: true` от Bot API. Ограничение 5 заявок за 15 минут, honeypot, минимальное время заполнения, проверка курса и согласия на сервере. При сбое ответ 502, пользователь может попробовать снова или написать напрямую; повторная попытка после сетевого таймаута может привести к дубликату сообщения. Нет обещания автоматического ответа клиенту, выдачи доступа или очереди повторных отправок.

Приложение не сохраняет заявки в БД и не пишет их в логи. Данные остаются в Telegram: владелец должен определить и соблюдать срок хранения, удалять сообщения, ограничивать доступ и учитывать копии/экспорты. Факт согласия передаётся с заявкой и временем. Если требуется аудит версии документов или хранение заявок в РФ, до production нужна отдельная согласованная схема хранения и доставки; наличие SQLite для настроек не решает локализацию данных заявителей.

`TRUST_PROXY=false` по умолчанию: лимит общий для пользователей сервера. Установите `true` только за ingress, перезаписывающим `X-Forwarded-For`, с закрытым прямым доступом к Node. Тогда IP используется только в виде HMAC для короткоживущего лимита. Несколько процессов на одном сервере разделяют лимиты через SQLite, несколько серверов требуют общей БД/Redis. В примере Nginx лимит тела 128 КБ, приложение дополнительно ограничивает принятый JSON.

## Оплата

По умолчанию все карточки предлагают уточнить условия в Telegram. Это информация, а не подтверждение наличия договора. Администратор может выключить метод или включить подтверждённую официальную HTTPS-ссылку. Ссылка не создаёт платёж, не проверяет его и не выдаёт доступ.

Для полноценной оплаты необходимо выбрать провайдера, получить договор, тестовые и боевые ключи, согласовать чеки, затем реализовать контракт `PaymentProvider`. Сервер создаёт заказ с ценой из БД, а не из браузера; webhook проверяет подлинность, сумму, валюту, order ID, повторную доставку и статус. Только подтверждённый сервером платёж меняет статус заказа. До реализации этих частей кнопки оплаты на самом сайте не активируются. Неподключённые Сбербанк, Т-Банк и Сплит не выдаются за работающие.

## Развёртывание в РФ

Для MVP подходит один VPS в российском дата-центре (например, у Timeweb Cloud или Selectel; регион и условия подтвердить при заказе), Node 24, постоянный SSD, HTTPS и Nginx. Практическая исходная конфигурация: 2 vCPU / 2–4 ГБ RAM. SQLite выбран для небольшого редактора с одним владельцем: нет отдельного сервиса БД и абонентской платы за CMS. Он требует постоянного диска и резервного копирования; serverless с эфемерным диском не подходит. При нескольких экземплярах перейти на PostgreSQL и общий лимитер.

Стоимость зависит от актуального тарифа VPS, диска, резервных копий, домена и комиссий провайдера платежей. Планируйте ориентировочный бюджет 1–3 тыс. ₽/мес. на небольшой сервер и бэкапы, а не подтверждённую цену конкретного тарифа. Домен, эквайринг и Notion оплачиваются отдельно при необходимости. Бесплатный dev-режим не означает бесплатный production.

Можно использовать Dockerfile (`docker build --build-arg SITE_URL=https://ваш-домен -t kaleadoskill .`), затем постоянный volume на `/app/data`, env-файл с правами 0600 и опубликованный только на loopback порт `127.0.0.1:3000:3000`. Настройки домена `SITE_URL` передавайте и при сборке, и при запуске: robots/sitemap и метаданные формируются с этим значением. Для обычного Node тоже задайте `SITE_URL=https://ваш-домен` до `npm run build` и при запуске. Без домена canonical не выдумывается, индексация запрещена, sitemap пуст.

Для выбранного пользователем домена kaleadoskill.ru подготовлены `deploy/compose.yaml` и `deploy/Caddyfile`: постоянная SQLite, autorestart, автоматический HTTPS и закрытый внешний порт приложения. Контейнер, встроенные документы и синтаксис Compose/Caddy проверены в облачной среде. Домен и VPS пока не предоставлены, внешний хостинг и выпуск сертификата не проверены. Подробные шаги — `docs/LAUNCH.md`. `deploy/nginx.conf.example` остаётся альтернативным непроверенным шаблоном.

## Бэкапы

`node scripts/backup.mjs /secure/backup/directory` создаёт согласованную SQLite-копию онлайн через backup API, без dev-зависимостей. Скрипт читает DATABASE_PATH из окружения процесса: задайте тот же путь, что у приложения (сам скрипт не загружает .env.local). Настройте cron, хранение вне web-root, шифрование и срок хранения. Бэкапировать также утверждённые PDF и env через секретное хранилище, не Git. Альтернатива: остановить приложение и скопировать всю директорию `data` вместе с WAL/SHM; не копировать один активный SQLite-файл без backup API.

Для восстановления остановить только собственный сервис, сохранить текущие данные, заменить БД проверенной копией, проверить права владельца, запустить сервис и проверить контент и вход. Бэкапы содержат настройки и лимиты, но не заявки. Удаление заявок выполняется в Telegram согласно утверждённой политике.

## Проверки

```sh
npm run typecheck
npm test
npm run build
# Если Chromium установлен системно:
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
# Иначе сначала:
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты используют отдельную временную БД и тестовые пароли, запускают dev-сервер на 3100 и закрывают его после проверки. Серверный Telegram-тест подменяет fetch и не отправляет реальные сообщения. Отчёт фактических проверок находится в `docs/VALIDATION.md`.

## До публикации

- Предоставить телефон либо согласовать Telegram как единственный контакт, уточнить фактический формат и график обучения.
- Утвердить политику, оферту и согласие; добавить реальные документы. Проверить обязательные сведения об исполнителе и образовательной деятельности, применимость лицензирования, рекламу, дистанционные услуги, возвраты и чеки со специалистом. Проект не содержит выдуманных юридических условий.
- Проверить российские требования к локализации и передаче персональных данных, особенно отправку в Telegram и использование Notion. Определить сроки хранения и удаления, контроль доступа.
- Настроить пароль админа, session secret, домен, HTTPS, ingress, постоянный диск и бэкапы; проверить восстановление.
- Настроить и проверить реальный Bot API, затем включить форму.
- Активировать только договорённые способы оплаты; для API-платежей завершить интеграцию и тесты.
- Проверить сайт на production-домене, SEO, мобильные устройства, клавиатуру, ошибки доставки и актуальность документов.

Сайт подготовлен к разработке и демонстрации; документы предоставлены и встроены как проекты редакций. До публичного коммерческого запуска остаются правовая проверка их условий, домен, VPS и фактические интеграции.
